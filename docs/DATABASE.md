# Database

Postgres. The source of truth for the schema is `SCHEMA` in `app.py`; `schema.sql` is generated from it. Both are idempotent: safe to re-run, and they upgrade an older database.

## Conventions

- **Money** is integer cents (`*_cents`). Never use floats.
- **Times** are Unix seconds, stored as `BIGINT`, and shown in `STORE_TZ`.
- **Flags** are `INTEGER` 0/1 (`active`, `wholesale_only`, `wholesale`).
- **Ids** are `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- **Row-level security** is on for every table, with no policies. The app connects as the tables' owner, which RLS doesn't restrict.
- **Legacy column names.** `retail_cents` is the **public price**, `wholesale_cents` is the **member price**, `wholesale_only` means **members only**, and `orders.wholesale` means the order was placed by a member (always 1 now). The names date from the first version; the UI uses the new words.

## Tables

| Table | Holds | Notes |
|---|---|---|
| `users` | Members and staff | `role`: `customer` or `staff`. `biz_status` is the membership: `pending` (registered, unpaid or awaiting approval), `approved`, `rejected` or `revoked`; it's NULL for staff. `pw` is a scrypt hash, `salt$hash`. `company` and `license_no` are optional. |
| `sessions` | Logins | `token` is the SHA-256 of the cookie value, never the raw token. `csrf` is the per-session form token. Deleted on logout and on password reset. |
| `products` | Catalog | Has `sku` (unique), `stock` (`CHECK >= 0`) and `image_id`, the current photo. |
| `drivers` | Delivery people | Have no login. `phone` must include the country code, because it's used for `wa.me` links. |
| `orders` | One per order | `status` is one of `STATUSES`, and `payment` is one of `PAYMENTS` (`due_on_delivery`, `paid_cash`, `paid_transfer`). `collect_cents` is what the driver collects. `address` is the member's typed address. `lat`/`lng` is the optional exact pin, and `pin_address` is the map's address for that pin. `receipt_image_id` is the latest transfer receipt. |
| `order_items` | Lines of an order | `name` and `unit_cents` are copied at order time, so later price changes don't rewrite history. |
| `audit` | Everything that happened | `detail` starts with `#<order id> ` for order events and `APP-<user id>` for account events; the order and member pages filter on those prefixes. Never deleted. |
| `ads` | Ads on the games pages | `placement` is `top`, `grid`, `side` or `pregame`. Either `image_id` + `link` (a banner) or `code` (ad-network tag). `countries` and `hide_countries` are space-separated 2-letter codes (blank = no rule). `gambling=1` holds the ad: it is never served on the all-ages games pages. `clicks` counts banner clicks. |
| `images` | Photos | `kind` is `product`, `receipt` or `ad`; `data` is `bytea`, about 30 KB after the browser shrinks it. Product photos are replaced, and the old row is deleted. Receipts keep only the latest per order and expire after `RECEIPT_DAYS`. |

Apply `membership_store_ads` before deploying the ads version:

```sql
SET ROLE store_app;
SET search_path = store;
ALTER TABLE images DROP CONSTRAINT IF EXISTS images_kind_check;
ALTER TABLE images ADD CONSTRAINT images_kind_check CHECK(kind IN ('product','receipt','ad'));
CREATE TABLE IF NOT EXISTS ads(
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, name TEXT NOT NULL,
  placement TEXT NOT NULL CHECK(placement IN ('top','grid','side','pregame')),
  image_id BIGINT REFERENCES images, link TEXT, code TEXT, gambling INTEGER NOT NULL DEFAULT 0,
  countries TEXT NOT NULL DEFAULT '', hide_countries TEXT NOT NULL DEFAULT '', active INTEGER NOT NULL DEFAULT 1,
  clicks BIGINT NOT NULL DEFAULT 0, created_at BIGINT NOT NULL);
ALTER TABLE ads ENABLE ROW LEVEL SECURITY;
RESET search_path;
RESET ROLE;
```

### Applying a change to the live database

Write the change in `SCHEMA` first (idempotent), test it locally, then apply only the new statements as `store_app`. That way the new objects are owned by the right role.

```sql
SET ROLE store_app;
SET search_path = store;
ALTER TABLE orders ADD COLUMN IF NOT EXISTS example TEXT;   -- your new statements
RESET search_path;
RESET ROLE;
```

Run it in the Supabase SQL editor, or as a named migration. Afterwards:
- check Supabase's security advisor: "RLS enabled, no policy" on `store.*` is expected and intended.
- regenerate `schema.sql`.

### Rotating the store's database password

```sql
ALTER ROLE store_app PASSWORD 'new-long-random-password';
```

Then update `DATABASE_URL` in Vercel and redeploy.

## Backups and space

- **Exports.** Staff export CSVs from `/admin/export`, the owner's manual backup. Supabase's own backups depend on the plan.
- **Free plan size.** The free plan has a database size limit. Images are the only thing that grows fast, and they are capped by the automatic cleanup. `/admin/export` shows the space used by images.
